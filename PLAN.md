# Glossa Catholica — development plan

A living document: what is left, why it matters, what it depends on, and honest sizing — organized so that someone can answer "what should I work on next, and in what order." Distinct from `docs/decisions.md`, which is an **append-only historical log** of decisions as they were made (read it for _why_ something is the way it is, and when it changed).

This document is the opposite shape: it gets rewritten as reality changes and has no history of its own. **It does not restate what shipped.** A phase that lands leaves this file entirely — its "why" belongs in a new `decisions.md` entry, not in a "recently done" section here that would grow without bound and duplicate the log.

Sizing is stated honestly throughout: a measured figure is presented as one (with how it was measured); anything else is explicitly labelled an estimate. Where sizing isn't yet knowable — an item nobody has scoped in detail — that is stated too, rather than guessed at.

## Sequencing and recommendation

Nothing here gates anything else; order is a priority argument, not a dependency one.

- **The row that used to lead this list has been paid off.** #3 led on a claim no other gap could make — that it was work which _revealed_ something rather than adding something, an apparatus that cost a crawl and rendered nowhere. That is no longer true: the Douay-Rheims's notes and arguments are on the page as of 2026-08-25. What remains of #3 is a question about a different surface, and it is small.
- **Nothing else here gates anything.** #8 was long assumed to wait on #5's sigla table; it does not. The CCC cites conciliar documents by siglum and encyclicals by spelled-out title, and both already resolve — the sigla that remain unresolvable name works that are not in the corpus at all, so no table makes them linkable.
- **#11 is the big one now, and it is a schema problem wearing a scraping costume.** Do not start it by writing a scraper. The four decisions in `docs/research/haydock.md` are the work; the crawl is 22 minutes.

**Recommended order:**

1. **#4 design pass.** It moves up: #3 no longer needs it as a companion, but #3 has just put four new typographic surfaces on the page (the sidenote, the chapter argument, the four heading levels, the apparatus colour on a Bible marker) that were designed against placeholder colours and should be reviewed as a set. The Matos Soares apparatus now exercises all of them at scale — 5,733 headings and 3,013 notes — where the Douay-Rheims exercised them sparsely.
2. **The cheap, no-fetch, already-measured tier**, most of which was paid off on 2026-08-25: the six lemma corrections adjudicated in `docs/research/douay-rheims-lemma-audit.md` were filed (the Douay-Rheims corrections layer went from 14 entries to 20, the lemma oracle from 72 strays to 66), #8's reverse citation index was built and rendered, and #9's divergence table was classified and checked. What is left of the tier is **#7 the Fathers citation pass**, plus the two remainders those two rows named — `Ibid.` in #8 and the reader-facing disclosure in #9.
3. **#11 Haydock** — the largest and most interesting addition, once its schema is settled.
4. **#2 search** — the largest unscoped item; needs a prototype before it can be planned.
5. **#1 Latin for the CCC and documents** — scoped below.
6. **#5 `related` / #6 Appendix B** — lowest urgency; each still needs a research pass in `docs/research/` style before implementation is scopeable.

## Latin — the CCC and the document families

`docs/research/latin-sources.md` establishes, with live 2026-08-15 fetches, that Latin is fetchable and addressable for all 16 Vatican II documents, the CCC, and a real if uneven slice of encyclicals — notably filling exactly the gap where Portuguese is weakest, because Latin was the actual promulgation language. **The Compendium has no Latin edition anywhere on vatican.va**: a permanent, source-level fact to design around, not a scrape target.

The architecture question this phase used to be blocked on — UI language vs. content language — was decided and built on 2026-08-23; `docs/decisions.md` has the reasoning and the alternatives considered. What remains:

- **The two-URL-template reality** (`_lt.html` suffix for the "archive" template families vs. a `/la/` path segment for the "content" families, `latin-sources.md` §4) needs a scraper design. This is the same split `vatican_docs.py` already routes for EN/PT, so it is a third `lang` argument rather than a new family — but nobody has written it.
- **`check_language_symmetry` hardcodes two languages at both ends.** `_WORK_ID_RE` accepts only `en`/`pt` as trailing language codes, so a Latin work directory would be silently skipped rather than checked, and the comparison is pairwise-for-exactly-two. Generalising the mechanism is mechanical.
- **What that check should _assert_ once Latin is in it is not mechanical, and is undecided.** It currently reads a section-count mismatch as evidence of a parsing defect, which is reasonable between two independent translations. Latin is the text the vernaculars translate, so a Latin/vernacular mismatch may be what translation _is_ rather than a bug. Comparing each vernacular **against Latin when Latin is present**, rather than comparing all present languages pairwise, is the plausible better check. The Bible offers a precedent worth reading first: there, adding the base text turned an unresolvable "both are faithful" into an adjudicable question (`docs/decisions.md`, 2026-08-23), which argues for the against-Latin shape.

  This is flagged here so it is not rediscovered mid-implementation — the way `check_language_symmetry` itself was originally motivated by a real, found defect (`docs/research/vatican-documents.md` §6).

- **The Latin CCC's populated `abbrev_lt.htm`** (`latin-sources.md` §5) is a second, independent path to #5's abbreviations gap — still not chosen, still not needed.
